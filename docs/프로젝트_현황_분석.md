- 민감 정보: `web/js/config.local.js`의 값은 출력하거나 분석 결과에 복사하지 않음

## 현재 상태

저장소는 기획서만 있는 빈 프로젝트가 아니다. HTML·CSS·Vanilla JS 화면, 자체 호스팅 JS 라이브러리, Supabase 초기 SQL, DB 설계서, 화면별 구현 지시서, PC·모바일 미리보기가 이미 존재한다. Git remote `origin`은 사용자가 알려 준 `https://github.com/smjjang-dev/motionnine`과 일치하고, `main`은 `origin/main`을 추적한다. 점검 때 HEAD는 `b0d4a6c`였다. 점검 당시 작업 디렉터리는 깨끗했으며, 이 분석·구현 준비 작업에서 새 문서 2개와 와이어프레임 변경 1개를 만들었다. 이 변경은 아직 commit/push하지 않았다. 프로젝트 안내에는 빌드 도구·패키지 설치가 필요 없는 정적 사이트라고 되어 있어, npm/npm test를 임의로 추가하지 않았다.

## 주요 미결정·위험 항목

1. **실제 외부 연결 여부:** GitHub 원격 설정은 확인했다. 이는 Cloudflare가 이 저장소를 자동 배포하도록 연결됐다는 뜻은 아니다. 로컬 설정 파일도 존재하지만 유효 key·로그인 성공·DB 연결·Pages 배포 성공을 입증하지 않는다. Cloudflare 연결과 브라우저 실제 로그인을 따로 확인해야 한다.
2. **정적 Pages 설정 반영:** 런타임 config가 git-ignore된 로컬 `config.local.js`를 동적 import한다. 그 파일은 정적 `web/` output에 자동 포함되지 않는다. Pages URL·publishable key가 배포물에 안전하게 주입되는 방법을 구현해야 실제 호스팅에서 인증과 DB 호출이 동작한다. 이 설정을 해결하지 않으면 홈페이지가 배포되더라도 사용자가 발주를 관리할 수 없다.
3. **주문자 개인정보 범위:** 현재 schema·등록 폼은 필수 주문자 실명과 휴대폰 번호를 수집하며, 선택 이메일도 포함한다. 앞선 업무 요구사항에 있던 항목이 아니므로 데이터 목적·수집 필요성·보관 기간을 먼저 확정한다.
4. **데이터 시드·첫 관리자:** Auth 가입 이후 UUID를 이용하는 bootstrap owner 순서가 필요하다. 관리자·실제 이메일이 준비되지 않으면 업무 화면 데이터 접근을 테스트할 수 없다.
5. **인증 메일:** Supabase 기본 SMTP를 일반 신규 가입자의 인증 수단으로 보장하지 않는다. 무료 Resend는 보유·인증 도메인, 무료 Gmail SMTP는 앱 비밀번호 허용 여부에 달려 있다. 실제 외부 주소로 받고 링크를 확인해야 한다.
6. **PC/모바일 화면 명세:** 기존 wireframe과 `web/html/` 운영 화면을 한 소스 원본으로 착각하지 않는다. 정적 wireframe은 샘플 데이터/설명용이고, `web/` 파일은 Supabase 연동을 전제한 구현 화면이다.
7. **마이그레이션 선택:** 신규 DB에는 주문자 필드를 포함한 현재의 초기 SQL 전체를 1회 실행한다. 이미 구축된 DB라면 이전 적용 여부를 확인해 추가 migration 적용 순서를 따른다. DB 상태 확인 전 파일을 반복 실행하지 않는다.
