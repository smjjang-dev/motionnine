# 07 W-07 관리자설정 — 구현 지시서 (owner 전용)

## 1. 목적·범위

승인 대기·활성·중지 목록, 정원(3~5)·역할 변경, 승인/중지 이력. 전부 설정행 잠금 + 감사.
와이어프레임: `web/html/admin.html` · JS 신규: `admin.js` · 접근: `is_owner()` RPC 선검사, 일반 admin은 진입 차단 + API도 차단.

## 2. UI 구성

1. `.bar`: `관리자 설정` + `owner 전용 · 일반 admin 접근 불가`.
2. `.summary` 정원: `정원: 활성 {n} / 최대 {m}` + `.quota` 바 + 규칙 3줄(마지막 owner 보호·축소 금지·UUID 기준) + select(5/4/3) + `[정원 변경 → update_admin_limit]`.
3. `승인 대기 (n)`: 이름·이메일 / 인증(확인됨/미확인) / 신청일 / `[승인 manage_member]` `[거절]`. 미확인 계정 승인 버튼 disabled.
4. `활성 (n)`: 이름 / 역할(owner/admin) / 상태 pill / `[중지]` `[owner 승격]` (본인 행은 `—`).
5. `중지 (n) · 이력`: 대상 / 액션 / 처리자·시각 / `[재활성화(정원 검사)]`.

## 3. RPC 명세 (§9.1)

- 조회: owner 전용 목록 RPC (Auth 이메일·인증상태 최소 반환).
- `manage_member(action, target)`: approve/suspend/reactivate/reject/change_role — 승인 시 설정행 잠금 + 활성 정원 + 승인 자격 재검증. 한도 초과 → `ADMIN_LIMIT_REACHED`, 마지막 owner 중지·강등 → `LAST_OWNER_REQUIRED`.
- `update_admin_limit(n)`: 3~5만 허용, 현재 활성보다 낮게 축소 금지.
- 전원 `admin_audit_logs` 기록 (bootstrap/approve/suspend/reactivate/reject/change_role/change_limit).
