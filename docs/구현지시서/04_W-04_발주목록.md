# 04 W-04 발주목록 — 구현 지시서 (핵심)

## 1. 목적·범위

발주 조회·검색·필터·집계·페이지네이션·등록 진입·목록 PDF 진입. 기본 화면.
와이어프레임: `web/html/orders.html` · JS 신규: `order-api.js`, `order-list.js` · 재사용: `common.js`.

## 2. UI 구성 (orders.html 현행 순서 유지)

1. `.bar`: `[모션나인 발주관리] 발주목록` + `{이름}({역할}) · 로그아웃`.
2. `.stage-cards` 4개: 접수(1)12 / 준비(2)8 / 발송(3)5 / 완료(9)31 — 클릭 시 단계 필터 적용.
3. `.filter` 바:
   - 검색 input `.grow` (placeholder: `검색: 거래처·주문자·제품·제품코드·발주번호`) + `[검색]` (`.btn.primary.sm`)
   - `발주일 시작 ~ 종료` (date input 2개) + 단계 select (전체/접수/준비/발송/완료)
   - `[초기화]`(ghost) `[PDF(목록 내보내기)]` `[+ 발주 등록 → order-form.html]`(primary)
4. 힌트 1줄: 집계 기준·KST·정렬·페이지 안내.
5. PC: `table.grid.desktop-only` 8열 (발주번호/발주일/거래처/주문자/제품·코드/수량·합계·단계). 수량·합계 `.num` 우측정렬. 발주번호 → `order-detail.html?id=`.
6. 모바일: `.cards-m .ocard` (번호+pill / 거래처·주문자·제품·수량 / 일시+합계).
7. `.pager`: 이전/번호/다음 + 20·50건 select.

## 3. 데이터 명세

- RPC: `search_orders(filters, page, page_size, sort)` — SECURITY INVOKER + RLS, page_size ≤ 50 강제.
- filters: `{q, date_from, date_to(KST), stage}` / sort 고정: `ordered_at DESC, id DESC` (허용 목록 외 거부).
- 검색: 거래처명·주문자명·주문자 연락처·제품명·제품코드·발주번호 OR 부분일치, `%_\\` escape, 파라미터 바인딩 (동적 SQL 금지, §6.6).
- 날짜: `date_from 00:00 KST 이상 ~ date_to+1일 00:00 KST 미만`.
- 단계 건수: 검색어·기간 적용 + **단계 필터 제외** 별도 집계 (와이어프레임과 동일 숫자 규칙).
- URL 쿼리로 상태 유지: `?q=&from=&to=&stage=&page=&size=` — 새로고침·공유 가능.

## 4. 상태 분기 (`.anno` 그대로 구현)

- 결과 없음: `조건에 맞는 발주가 없습니다. [필터 초기화]`
- 로딩: 스켈레톤 행 3개.
- 실패: `목록을 불러오지 못했습니다. [재시도]` + 에러코드 한글 매핑 (DB 원문 노출 금지).
- 삭제건: 목록·검색·집계 전부 제외. 긴 제품명은 `…` + 상세에서 전체.

## 5. 목록 PDF 진입

`[PDF]` 클릭 → 확인 모달: `현재 조건 전체 N건 중 최대 200건 [현재 페이지 | 조건 전체]` → 10번 지시서 export RPC 호출. 200건 초과 시 `기간·필터를 좁혀주세요.`

## 6. 반응형

- 992px+: 전체 테이블. 767px-: 테이블 숨김 + 카드 표시 (이미 `responsive.css` 구현됨 — 유지).
- 필터 바는 wrap 되어 가로 스크롤 없이 동작.

## 7. 수용 기준
