# 02 W-02 가입·인증·재설정 — 구현 지시서

## 1. 목적·범위

이메일 가입·인증메일·만료/실패·재설정 4상태. 가입 직후 서버가 `role=admin, status=pending` 강제(§4.2-2, 메타데이터 신뢰 금지).
와이어프레임: `web/html/signup.html` (탭 4개 + `.tabpane`) · JS: `common.js` + `tabs.js` 유지 + `auth.js` 확장.

## 2. 탭별 UI·동작

### ① `#t-join` 이메일 가입 폼
- 필드: 표시 이름* (100자, trim, 공백만 불가) / 이메일* / 비밀번호* (8자+, Supabase Auth 정책 준수).
- `[가입 신청]` → `signUp` → 성공 시 `#t-sent`로 전환 + `58초` 재전송 쿨다운 타이머.
- 서버 트리거가 `app_members` pending 생성. 클라이언트가 role/status를 보내도 무시됨을 주석 명시.

### ② `#t-sent` 인증메일 발송됨
- `.okbox`: `인증 메일을 보냈습니다. {email} 받은편지함(스팸함 포함)에서 24시간 내 링크를 눌러주세요.`
- `[인증메일 다시 받기]`: 쿨다운(58초) + 속도 제한. SMTP 한도 시: `발송 한도에 도달했습니다. 잠시 후 다시 시도하세요. Google 로그인이 연결된 경우 Google로 로그인할 수 있습니다.`

### ③ `#t-fail` 만료·실패·재전송
- 진입 조건: 만료 링크 / 이미 사용됨 / 다른 브라우저 오픈(PKCE verifier 없음).
- `.errbox` + `[새 링크 받기]` (재전송) + `[로그인으로 돌아가기 → login.html]`.
- 다른 브라우저 케이스: `인증은 요청한 브라우저에서 완료하세요. [새 링크 받기]` 또는 token-hash 흐름(§11.2-7).

### ④ `#t-reset` 비밀번호 재설정
- 이메일 입력 + `[재설정 링크 보내기]`. 성공/실패 메시지 통일: `입력한 주소로 안내를 보냈습니다.`
- 실제 메일 발송은 Custom SMTP (Resend Free 또는 전용 Gmail, §14.3). 기본 SMTP(시간당 2건)는 시연용 부적합.

## 3. 공통 규칙

- Confirm email 활성화. 비밀번호는 Auth에만 저장, 업무 테이블 저장 금지.
- 가입·재전송·재설정에 서버 속도 제한 + 필요 시 CAPTCHA. 프런트 버튼 비활성화만으로 한도 소진 방지 불가(§14.5).
- 메일 미수신으로 인증 자동 완료 처리 금지. 무료 한도 초과 시 무한 재시도·유료 전환 금지.
