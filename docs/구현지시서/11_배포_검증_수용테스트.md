# 11 배포·검증·수용테스트 — 구현 지시서

기획 §11·§12·§14. 수치·URL은 시연 직전 재확인 (본 문서는 2026-09-27 기준).

## 1. 배포 순서 (§11.2)

1. 업무 확정: §13 7항 (단가·배송비·품목·정원·owner·번호날짜·SMTP) — 미확정 시 기본값으로 진행.
2. Supabase Free 프로젝트 생성 (리전: 시연 망에서 가장 빠른 곳, 이후 변경 불가).
3. 마이그레이션 적용: 테이블·CHECK·UNIQUE·인덱스·RLS·RPC·감사 트리거 (Git 버전관리, 파괴적 변경 전 백업).
4. Auth: Confirm email ON + Custom SMTP (Resend Free 보유도메인 우선, 없으면 전용 Gmail) + Google provider (callback `https://<ref>.supabase.co/auth/v1/callback`).
5. Cloudflare Pages에 `web/` 배포 → `*.pages.dev` 고정 URL 확보. 배포 전 "5.1 설정값 주입" 반영.

### 5.1 설정값 주입 (방안 A, 결정됨)

브라우저 코드([web/js/config.js](../../web/js/config.js))는 `web/js/config.local.js`를 동적 import한다. 이 파일은 `.gitignore` 대상이라 저장소에는 없고, 로컬 개발자가 `config.local.example.js`를 복사해 각자 만든다. 배포용 값(`SUPABASE_URL`·`SUPABASE_ANON_KEY`(publishable)·`SITE_URL`)은 비밀이 아니지만(브라우저 노출 전제, RLS가 보호), 이 저장소는 GitHub public이므로 git에는 커밋하지 않고 **Cloudflare Pages 빌드 시점에 생성**한다. 코드 변경 없음.

1. Cloudflare Pages 프로젝트 → Settings → Environment variables (Plaintext, secret 아님)에 등록: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SITE_URL`, `APP_ENV=prod`.
2. Settings → Builds → Build command에 등록 (npm/프레임워크 불필요, Cloudflare 빌드 이미지 기본 셸 사용):
   ```bash
   mkdir -p web/js && cat > web/js/config.local.js <<CFG
   export const LOCAL_CONFIG = {
     SUPABASE_URL: "$SUPABASE_URL",
     SUPABASE_ANON_KEY: "$SUPABASE_ANON_KEY",
     SITE_URL: "$SITE_URL",
     ENV: "$APP_ENV",
   };
   CFG
   ```
3. Build output directory는 그대로 `web`, Framework preset은 None.
4. 배포마다 `config.local.js`가 새로 생성되므로 값 교체(키 로테이션 등) 시 Pages 환경변수만 갱신하고 재배포하면 된다. git에는 절대 이 값을 커밋하지 않는다.
6. Supabase Site URL=시연 주소, allowlist에 `/html/login.html` 콜백·confirm·reset 경로 등록.
7. 이메일 템플릿 링크 ↔ 콜백 연결, 다른 브라우저 오픈 케이스 검증.
8. 최초 owner 초기화 SQL (검증된 Auth UUID 지정, 정원 검사 포함 — 선착순 승격 금지).
9. 나머지 관리자 승인 → 가상 거래처 시드 → PC·모바일 시연.

## 2. 무료 한도 점검표 (§14.4)

Pages 빌드 월500회·파일 20,000개·25MiB / Supabase DB 500MB·egress 5GB·Auth 50,000 MAU·프로젝트 2개·7일 미사용 중지 /
SMTP별 한도(기본 시간당2건 / Resend 월3000·일100 / Gmail 소량 + Supabase Auth 시간당30) / 유료 전환 자동화 금지.

## 3. 수용테스트 (통과해야 시연 완료, §12.1)

- 접근: 미로그인·pending·suspended API 직접 호출 → 전부 차단.
- 정원: 4명 활성에서 2건 동시 승인 → 1건만 성공. 마지막 owner 중지·강등 → 거부.
- 철회: 로그인 중 중지 → 다음 요청부터 차단. 위조 메타데이터 → pending/admin 강제.
- 이메일: 미확인 차단·정상·만료·재전송·재설정 + 한도 소진 시 안내 (무한재시도·유료전환·미인증승인 금지).
- 입력: 기본값(상태1·배송비3000·VAT N·포함Y·KST now) / 필수(주문자 포함)·휴대폰 형식·이메일 형식·MOQ·범위 거부 / §7.2 4조합 + 0원 + 반올림경계 일치.
- 번호: 동시 100건 중복 0 / 연타 1건 / KST 자정 경계 / 99999 상한 롤백 / 소급 입력 번호 유지.
- 수정: 동시 version 1건 성공 / 위조(created_by·금액·번호) 불가 / 삭제→제외→owner 복원 동일번호.
- 검색: 한글·특수문자·KST 경계 / 다운로드: 장문·200건·모바일 저장 / PC·모바일 브라우저 4종.
- 권한: 공개키·RPC·뷰 직접 접근 우회 불가 / 백업 복원 일관성.
