# 05 W-05 등록·수정 — 구현 지시서 (핵심)

## 1. 목적·범위

발주 등록 + 수정 + 삭제 진입. 입력 순서·유효성·금액 미리보기·낙관적 잠금·중복 방지.
와이어프레임: `web/html/order-form.html` · JS: `order-form.js`(미리보기 유지·확장) + 신규 `order-api.js`.
모드: `order-form.html`(등록) / `order-form.html?id=&v=`(수정, version 확인).

## 2. 폼 구성 (순서 고정, §5.3)

| 순서 | 필드 | 규칙 (DB CHECK와 동일) |
|---|---|---|
| 0 | 발주번호 | 읽기전용 `disabled`, `저장 시 발급 — 예: 20260927-00003` + 도움말(번호날짜≠발주일 가능) |
| 1 | 거래처명* | varchar(100), trim, 공백만 불가 |
| 2 | 주문자* | varchar(100), trim 1~100, 실명 입력 |
| 3 | 주문자 연락처(휴대폰)* | varchar(20), `01X-XXXX-XXXX` (하이픈 선택, 예: 010-1234-5678), DB 정규식 CHECK |
| 4 | 주문자 이메일 | varchar(200), 선택, 빈 값 미저장(NULL), 간단 형식 CHECK |
| 5 | 발주일(KST)* | `datetime-local`, 초기값=`get_server_time()` KST, `+09:00` 명시 변환 |
| 6 | 제품명* | varchar(200), trim 필수 |
| 7 | 제품코드* | varchar(100), trim 필수, **발주 간 중복 허용** |
| 8 | 옵션 | varchar(500), 빈 값=NULL |
| 9 | 수량* `#f-qty` | 정수 1~1,000,000 |
| 10 | MOQ | 선택, 입력 시 1 이상 + `quantity >= moq` (미달 저장 차단, `MOQ_NOT_MET`) |
| 11 | 단가* `#f-price` | numeric 0~1,000,000,000, 기본값 없음(빈칸 허용하되 저장 시 필수) |
| 12 | 부가세 별도 `#f-vat` | N=포함(기본) / Y=별도, 문구 그대로 |
| 13 | 배송비 포함 `#f-ship` | Y=포함·추가0원(기본) / N=별도청구, 설명 병기 (§13-② 확정 전 유지) |
| 14 | 배송비* `#f-fee` | VAT포함, 기본 3000, 0~10억 |
| 15 | 발송단계* | 1접수(기본)/2준비/3발송/9완료. 건너뛰기·역행·완료 후 금액수정 시 사유 필수 |
| 16 | 변경 사유 | 조건부 필수 (위 경우), varchar(500) |

- 필수 `*` 표시, 오류는 필드 바로 아래 `.f-err`에 구체 문구. 저장 중 버튼 잠금 + 미저장 이탈 시 `beforeunload` 확인.

## 3. 금액 미리보기 (우측 `.summary`)

- ID 유지: 입력 `f-qty/f-price/f-vat/f-ship/f-fee` → 출력 `s-a/s-ps/s-pv/s-f/s-sv/s-t`.
- 식은 `order-form.js` 현행 §7.1 그대로 (수정 금지, 00번 참조). 입력 input/change마다 재계산.
- 문구: `금액 미리보기 (저장은 DB 확정값)`. 저장 후 응답의 확정값으로 다시 렌더링.

## 4. 저장 동작

- 등록: 진입 시 `crypto.randomUUID()` → `client_request_id`. `create_order(payload, request_id)` 호출. 재시도는 같은 UUID. 응답의 `order_no`로 상세 이동.
- 수정: `update_order(id, expected_version, payload, reason)`. `VERSION_CONFLICT` 시 `다른 관리자가 먼저 수정했습니다. [새 데이터 불러오기]` (자동 덮어쓰기 금지).
- 단계만 변경: `change_order_stage(id, expected_version, stage, reason)` 사용 (감사 `stage_change` 분리).
- 삭제: `.modal` 그대로 — 번호·거래처·주문자·제품 표시 + 사유* → `delete_order(id, expected_version, reason)` (논리삭제).
- 완료 상태 금액 변경: 추가 확인 다이얼로그 + 사유 필수.

## 5. 반응형

767px-: 1열 + `.sticky-save` 하단 고정 (취소/저장). `responsive.css` 유지.

## 6. 수용 기준

- [ ] 필수·공백·주문자 누락·휴대폰 형식·이메일 형식·MOQ·범위 14케이스 화면+DB 이중 거부.
- [ ] §7.2 네 조합 + 0원 + 반올림 경계에서 JS=DB=화면=출력 일치.
- [ ] 동시 등록 100건 번호 중복 0 / 저장 버튼 연타 1건(`client_request_id`).
- [ ] 같은 version 동시 저장 1건만 성공.

## 7. 체크리스트

- [ ] `payload`는 허용 필드만 (번호·작성자·감사·계산 필드 전송 금지, 서버가 거부).
- [ ] `number→numeric` 직렬화·정수 안전 범위 검증.
- [ ] KST 자정 전후 등록 테스트 (UTC 날짜와 무관하게 등록일 기준 발번).
