# 03 W-03 승인대기·중지 — 구현 지시서

## 1. 목적·범위

`pending`(승인대기) / `suspended`·`rejected`(중지) 계정의 게이트 화면. 본인 상태 + 로그아웃만 제공, 업무 메뉴·데이터 접근 원천 차단.
와이어프레임: `web/html/pending.html` (2카드: `.warnbox` + `.errbox`).

## 2. UI 구성

- 승인대기 카드: `관리자 승인 대기 중` + `{표시이름}({email})` + `pending` pill(`.p-pend`) + `대표 관리자에게 승인 요청이 전달되었습니다…` + `[로그아웃 → login.html]` `[내 상태 다시 확인]`.
- 중지 카드: `접근 권한이 중지되었습니다` + `문의: 대표 관리자(010-XXXX-XXXX)` + `[로그아웃]`.
- 문구 고정(§4.2-7): `관리자 승인 대기` / `접근 권한이 중지되었습니다` 외 임의 문구 추가 금지.

## 3. 동작 명세

- 진입 시 `get_my_access()` 1회 호출 → 상태별 카드 1개만 표시 (둘 다 표시하는 와이어프레임과 달리 실구현은 분기).
- `[내 상태 다시 확인]`: RPC 재호출. `active`로 바뀌면 `orders.html`로 이동.
- 보호 라우트: 모든 업무 페이지(`orders/order-form/order-detail/admin/trash`) 진입 전 `get_my_access()` 검사. `pending/suspended`면 `pending.html`로 리다이렉트.
- 로그아웃: 세션·메모리·쿼리 캐시 정리 후 `login.html`.

## 4. 수용 기준

- [ ] pending/suspended 계정의 발주·검색·집계·감사·내보내기 API 직접 호출 전부 차단.
- [ ] owner 승인 후 `[내 상태 다시 확인]` → 목록 진입.

## 5. 체크리스트

- [ ] 상태별 단일 카드 렌더링 (URL 파라미터 `?state=pending|suspended` 선택 지원).
- [ ] 5초 폴링 금지 (수동 새로고침만 — 불필요한 egress 방지).
