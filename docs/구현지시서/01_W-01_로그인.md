# 01 W-01 로그인 — 구현 지시서

## 1. 목적·범위

관리자 로그인 진입점. Google OAuth + 이메일/비밀번호. Apple 제외(§4.3).
와이어프레임: `web/html/login.html` · 스타일: `common.css` + `components.css` `.auth-box` · JS: `common.js` + 신규 `auth.js`, `supabase-client.js`.

## 2. UI 구성 (login.html 현행 그대로 구현)

1. `.logo-big` 모션나인 + `발주현황 관리 로그인` + `관리자 전용 · 내부용` 문구.
2. `[G Google로 계속하기]` (`.btn.google`, 최상단, min-height 44px).
3. `또는` 구분자 → 이메일 입력 (`#li-email`) → 비밀번호 입력 (`#li-pw`, highest 44px, 보기 토글 추가 권장).
4. `.err` 영역: 기본 숨김. 실패 시에만 표시 (문구는 4번 규칙).
5. `[이메일로 로그인]` (`.btn.primary` 전체너비, 저장 중 disabled + `로그인 중…`).
6. 하단 2버튼: `[회원가입 → signup.html]` `[비밀번호 재설정 → signup.html#t-reset]`.

## 3. 동작 명세

- Google: Supabase Auth PKCE → `https://<ref>.supabase.co/auth/v1/callback` → 최종 콜백에서 code 교환·에러 처리. 취소/실패 시 로그인 화면 복귀 + `Google 로그인을 완료하지 못했습니다. 다시 시도하세요.`
- 이메일: `signInWithPassword`. 성공 시 `get_my_access()` 호출 후 분기:
  `active` → `orders.html` / `pending` → `pending.html` / `suspended`·`rejected` → `pending.html`(중지 문구).
- 세션 저장: 기본 `sessionStorage` (탭 단위) + SDK 갱신 흐름 검증. 로그아웃 시 화면·메모리·쿼리 캐시 비움.

## 4. 예외·보안 문구

- 실패 메시지 통일 (계정 존재 여부 노출 금지): `이메일 또는 비밀번호를 확인하세요.`
- SMTP 고갈·OAuth 미설정 시: `현재 로그인 제공자에 문제가 있습니다. 대표 관리자에게 문의하세요.` + 유료 전환·자동 재시도 금지.
- `service_role` 포함 금지. redirect allowlist에 실 배포 URL만.

## 5. 반응형

767px 이하도 `.auth-box(max-width 440px)` 중앙 유지. 터치 44px. 키보드 포커스 순서: Google → 이메일 → 비밀번호 → 로그인 → 가입 → 재설정.

## 6. 수용 기준 (§12.1)

- [ ] 미확인 이메일 계정은 로그인 성공해도 업무 API 차단 (W-02/03 연계).
- [ ] Google 취소/실패 시 임의 계정 병합 없음, 안내 문구 표시.
- [ ] 중지된 관리자가 기존 토큰으로 orders API 호출 시 차단.

## 7. 개발 체크리스트

- [ ] `supabase-client.js`: URL/publishable key만 사용, 환경 분리 (시연/개발 URL 구분).
- [ ] `auth.js`: `signIn`, `signInWithGoogle`, `signOut`, `get_my_access` 분기, 콜백 code 교환.
- [ ] 버튼 잠금 (중복 클릭 방지), Enter 제출, 비밀번호 보기 토글.
- [ ] `noindex` 메타 유지, CSP 헤더(`_headers`는 배포 단계).
