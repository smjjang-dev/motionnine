# 08 W-08 삭제내역 — 구현 지시서 (owner 전용)

## 1. 목적·범위

논리삭제(`deleted_at IS NOT NULL`) 조회·복원. 번호·금액·이력 유지.
와이어프레임: `web/html/trash.html` · JS: `admin.js` 재사용 또는 `trash.js` 분리.

## 2. UI 구성

- `.bar`: `삭제 내역` + `owner 전용`.
- PC `table.grid.desktop-only`: 발주번호 / 거래처·제품 / 삭제시각·삭제자 / 사유 / `[복원]`.
- 모바일 `.cards-m .ocard`: 번호 + `삭제됨` pill(`.p-stop`) / 거래처·제품·사유 / 삭제시각·삭제자 + `[복원]`.
- 힌트: `일반 admin 접근 불가. 복원도 version 증가 + 감사 기록. 영구 삭제는 웹 UI 미제공(§4.1).`

## 3. 동작 명세

- 조회: 삭제건 전용 RPC 또는 `search_orders(include_deleted=true, owner only)`. 일반 admin 호출 → `ACCESS_DENIED`.
- 복원: `restore_order(id, expected_version)` — 금액·번호 유지, deleted 필드만 해제, version+1, 감사 `restore`.
- 복원 후: 일반 목록에 재등장, 상세에서 이력 확인 가능.

## 4. 수용 기준

- [ ] 삭제 후 일반 목록/검색/집계 제외, owner 복원 후 동일 번호·기록 유지.
- [ ] 일반 admin의 삭제내역·복원 직접 호출 차단.

## 5. 체크리스트

- [ ] 복원 버튼 확인 모달 (`{order_no}를 복원할까요?`).
- [ ] `VERSION_CONFLICT` 시 최신 삭제 상태 다시 로드.
